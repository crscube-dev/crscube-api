OpenAPI specification for the CRScube CTMS External API.

Scope

The 14 endpoints whose paths begin with /external/api/v1.1.

Tag Count Contents
sync 5 Site, Subject, SAE, PD/PV and SDV synchronization (PUT)
tracker 4 SAE, PD/PV, Risk and Issue Tracker lookups
project 3 Study lookup, sponsor project list, team list
mvr 2 MVR list, MVR type codes

Authentication

The sync endpoints (5 PUTs) require the X-API-Key header. Keys are issued per project; contact your CRScube representative for the value.

How to read the status codes

This API returns 400 even for unclassified errors. In practice 500 does not occur.

Situation Actual response
Validation failure, body parse failure, any other error 400
X-API-Key missing, mismatched or not configured 401 (INVALID_REQUEST)
No permission 403 (FORBIDDEN)
Project, study or code not found 404 (RESOURCE_NOT_FOUND)

All three causes of 401 share the same errorCode, INVALID_REQUEST. To distinguish them you must read error.debugMessage.

On the sync endpoints, a project that cannot be found produces 404 before the API key is even checked.

Response format

Both success and failure always carry status and responseLanguage.

success  { result, message, status: "success", responseLanguage }
failure  { error: { errorCode, debugMessage, ...additional }, message,
           status: "fail", responseLanguage }

The 5 sync endpoints (PUT) return an empty object in result. They do not report how many records were processed.

Common to list endpoints

  • page starts at 1. A value below 1 is corrected to 1.
  • If size exceeds the server limit it is silently capped, without an error.
  • The response result echoes the applied search conditions in filteredElements.
  • Every row carries deleted and no.

sync

External system to CTMS data synchronization (PUT). X-API-Key required. Each endpoint accepts at most 100 records per request, and the audit reason is recorded as a system synchronization.

Synchronize sites (teams)

Creates or updates the site (team) list of a project, up to 100 records per call.

A studyTeamKey greater than 0 marks the team as already synchronized. The audit reason is recorded as a system synchronization.

Authorizations:
externalApiKey
path Parameters
projectId
required
string
Example: SAMPLE-PROJECT

Project ID. On the sync endpoints (PUT) it also identifies the project whose API key is registered.

header Parameters
X-API-Key
required
string

API key for the sync endpoints (PUT) only.

Compared against the API key issued to the project.

  • Header missing or blank: 401 (INVALID_REQUEST, "Missing X-API-Key header")
  • No API key configured for the project: 401 ("API Key not configured for this study")
  • Value mismatch: 401 ("Invalid API Key")
Request Body schema: application/json
required

List MVRs

Returns the MVRs (Monitoring Visit Reports) of a project, page by page.

The default sort is team ID, then report number, then schedule key, all ascending. Overdue determination follows the overdueCondition default, LAST_SIGN.

now defaults to the server's current date and is used as the reference date for the overdue calculation.
